# QA: accessibility, offline, console (2026-10-10)

Scope: built web app, a fresh `vite build` of app/ at audit time, served on :5391. Driven with a copy of `tools/drive.py` at 360x640 and 412x915. L1.01 was walked on both tracks (A: A/L/X sittings, B: A/L/X sittings, 11 distinct screens each), plus one L2.01 sitting on track A, the home and onboarding screens, and a 200% font pass at 360x640. app/src was not edited. The audit scripts live in the session scratchpad, not in the repo.

Totals: **0 blockers, 4 major, 11 minor**. Passes are listed at the end.

## Findings

### Major

1. **Answer pills all have the same accessible name.** On every answer card the check pill is named "This one" (3 buttons with an identical name per screen). The card's play button is "Option N: play". A screen-reader user cannot tell which pill belongs to which card. WCAG 2.4.6, 4.1.2. `app/src/screens/l1steps.js:29-30` (`btn(c.label || 'This one', ...)`), and the same pattern in `app/src/gate.js:80-81`. Fix: pass `aria-label: `Choose option ${i + 1}`` on the pill and wrap each card in `role="group" aria-label="Option N"`.
2. **Focus is dropped on every screen change.** `mount()` does `root.replaceChildren(el)` and focus falls to `<body>` (verified: `document.activeElement` is BODY after the sitting mounts). A keyboard or switch user restarts from the top of the page each screen. WCAG 2.4.3. `app/src/main.js:17`. Fix: after `replaceChildren`, focus the screen's `h1`/`h2` (give it `tabindex="-1"`).
3. **The whole app is one `aria-live="polite"` region.** `#app` is live, so every `replaceChildren` makes a screen reader read the full new screen (cards, pills, "Option 1: play" etc.) on top of the spoken audio. This clashes with the audio instructions. `app/index.html:10`. Fix: remove `aria-live` from `#app`. Announce only a short status (for example "Question 2 of 4") in a dedicated live region, and use finding 2 to move focus to the heading.
4. **Timed answer window with no way to extend, and the countdown disappears under reduced motion.** The Level 1 check gate gives 40 s, then moves on. The visible countdown is a CSS `shrink` animation, and the blanket `* { animation: none !important }` removes it, so reduced-motion users get a timeout with no countdown. WCAG 2.2.1. Not exercised at runtime (L1.01 has no gates); found by reading `app/src/gate.js:56,96-98` and `app/src/style.css:99,129`. Fix: exempt the timer (`.timer i { animation: shrink linear forwards !important }`, since it is a progress indicator and not decoration), and add a "More time" control or lengthen `windowMs` when `prefers-reduced-motion` is set.

### Minor

5. **Tap targets under 48px.** `.close` is 44x44 (`app/src/style.css:70`, in a child's header on every sitting screen). `.opt-pick` is 75x44 (`style.css:98`, `min-height: 44px`; the child's main answer control). `.btn.small` is 40px high (`style.css:22`), which affects "Who is reading?", "Library" and "For grown-ups" on home (179x40, 83x40, 168x40). Everything else measured was 52px or more (speakers, ear 58, nodes 64, `.btn` 52). Fix: set 48px minimum on all three (`min-height: 48px`, `.close` 48x48).
6. **Waiting-state check pill is nearly invisible.** `.opt-pick:disabled` at `opacity: .35` gives the white tick on tinted accent a 1.66:1 contrast ratio (1.87:1 on track B) and 1.65:1 against the card. This state shows for several seconds on every screen while the voice speaks. The enabled pill passes (white on #2f6f8f is 5.54:1, 5.45:1 against the card). Disabled controls are formally exempt, but a low-vision learner cannot see where the answer buttons will appear. `app/src/style.css:254`. Fix: use `opacity: .6` (or a solid `#9db8c6` background with `#1f4a60` tick) and keep the 3px outline as the second cue.
7. **No explicit `:focus-visible` style.** Only `button:focus:not(:focus-visible){outline:none}` exists (`app/src/style.css:207`), so the browser default ring is used (computed `outline: auto`). On the dark accent buttons, the dark `.ear` and the pale `.opt` cards it is thin and low in contrast. WCAG 2.4.11/2.4.13. Fix: add `:focus-visible { outline: 3px solid #1b4f6b; outline-offset: 3px; box-shadow: 0 0 0 6px #fff; }`.
8. **The ear button is last in DOM and tab order, but top-right on screen.** It is appended to `<body>` after `#app` (`app/src/teacher.js:45-49`). Tab order on a sitting is close, speaker, ear, then wraps (the Next button, when shown, comes before it). It is also `position: fixed` and overlaps headings when the page scrolls at 200% font (seen on the A track "Question 1" screen). WCAG 2.4.3. Fix: insert it right after the close button in the header, or at least `tabindex` it into the visual order, and reserve space for it at large font sizes.
9. **Heading structure and page titles.** Every sitting screen has no `h1` (only `h2`), and `document.title` is always "Sound Out" (`app/index.html:6`, never updated in `app/src/main.js:17`). WCAG 2.4.2. Fix: set `document.title = `${screenName} - Sound Out`` in `mount()` and render the screen question as `h1`.
10. **Locked lessons are `disabled` buttons with no reason a keyboard or screen-reader user can reach.** Home has 301 (track A) and 180 (track B) disabled nodes. They are skipped by Tab, and the "locked, opens after the check" explanation exists only as a touch press-and-hold (`data-say` on a wrapper span). `app/src/home.js` (the `x.state === 'locked'` branch around line 46) and `app/src/teacher.js:56+`. Locked node labels are 2.7:1. Fix: use `aria-disabled="true"` (stay focusable) plus a visually hidden "Locked" suffix, and collapse locked runs into one summary button.
11. **Low-contrast text.** `.printed .tag` ("alien word" tag) is 4.4:1 (`#7a5ea8` on `#efe8fa`), `app/src/style.css:86`; fix: `#6a4d9a`. `.gu-msg` error text uses `--bad` (#c4553c), 3.96:1 on the paper, `style.css:198`; fix: `#a8432d`. `--good` and `--heart` are 3.76:1 and 3.78:1 on paper if they are ever used as text.
12. **Decorative cues too faint for low vision.** The idle-hint halo is yellow at 0.45 alpha (about 1.1:1 on paper), `app/src/style.css:149-157`. Stickers are `#d18b2b` at 2.5:1 (`style.css:51,126`). Both are the only visual cue for "tap here" and "you earned this". Fix: add a non-colour cue (a 3px accent outline for the hint; darken the stickers to `#a86a14`).
13. **Infinite animations with no pause when motion is not reduced.** `.path .node.open` pulses forever (`style.css:60`) and the Tilo stage breathes forever (`style.css:180`). `prefers-reduced-motion` is honoured, so this only matters for users who have not set the OS flag. WCAG 2.2.2. Fix: stop the pulse after about 5 s (`animation-iteration-count: 3`).
14. **Web offline needs a service worker if `dist` is ever hosted.** There is no service worker or manifest (`app/dist` has none). With Playwright `set_offline(True)` every `.ogg` fetch fails (`ERR_INTERNET_DISCONNECTED`, about 14 per track). That is correct for the Capacitor APK, which serves the bundle locally with `INTERNET` removed (`app/android/app/src/main/AndroidManifest.xml:7`). Fix: only if a hosted PWA is planned, add a precache service worker; otherwise ignore.
15. **Demo and tooling pages are copied into the build.** `app/public/` holds `compare.html`, `listen.html`, `voices.html`, `tilo-demo.html`, `audition/`, `compare/` and `*-data.json`. They are copied into `dist/` by Vite and would go into the APK on the next `cap sync`. They had no external URLs. The shipped `privacy.html:50` links out to policies.google.com and github.com (only on tap). Fix: move the review pages out of `public/` (or exclude them in `vite.config.js`), and keep the outbound links only if they are intended.

## Console, network and offline (all green)

- **Console:** 0 errors, 0 warnings, 0 pageerrors, 0 failed or 404 responses across L1.01 on track A and B at both viewports (11 screens each), one L2.01 sitting on track A, home and onboarding. The drive harness's own rules also passed (audio keys, no picture with printed word, Tilo poses A: celebrating, listening, speaking).
- **External URLs:** `grep -rE 'https?://'` over `app/src` and `app/index.html` finds only prose in `privacy.js`; no fonts, CDNs or analytics. The font stack is system-only (`Andika` is named with `Verdana`/system fallbacks, never fetched). Every network request recorded in the walks (147-185 per run) was to the local origin. Non-local requests were also aborted by a route handler and none were attempted.
- **Offline:** cold load from the built `dist` with all non-local origins blocked: onboarding, home, every L1.01 screen on both tracks and an L2.01 sitting (spell, blend, warm, tricky) work. Android has the `INTERNET` permission removed and cleartext disabled. See finding 14 for the browser-only caveat. The L2 walk was capped by the harness's own 570 s budget after the first sitting (L2.01:A:T), so sittings 2-5 of L2.01 were not checked, and track B L2 was not completed (run aborted to save the shared machine).

## Passes (no action)

- `lang="en"` on `<html>`; viewport meta allows zoom (no `user-scalable=no`).
- Every control that was visible had an accessible name (0 unnamed across all scans). Decorative SVGs, Tilo and the pictures are `aria-hidden` / `alt=""`. The grown-ups sheet is `role="dialog" aria-modal`, traps Tab and restores focus.
- Text contrast of body text is 14.2:1, muted 4.95:1 on paper (5.48:1 on card), white on accent 5.54:1 (track B 9.58:1). The only visible-text failures are in finding 11.
- `prefers-reduced-motion: reduce`: with `reduce` there were 0 running animations on home and over 6 s of a sitting, and the halo becomes a still ring (`style.css:157`); with `no-preference` there were pulse, breathe, halo, cheer. Mouth flap is guarded in code (`tilo.js:82`); it was not observed at runtime because no speech frames were caught in the 4 s sample.
- 200% font (`html{font-size:34px}`) at 360x640: no horizontal scroll, no clipped or overflowing buttons or cards on 11 screens per track (headings wrap and the page scrolls). Only the fixed ear overlap in finding 8.

## Fixes (2026-10-10, commit bdaf0a1b)

Re-checked on a fresh build at 360x640 (Playwright, scripts in scratchpad), plus a direct call into `gate()` for the timer.

**Major**
1. Pill names. Every pill now has its own name: "This one, option N" (the visible "This one" stays inside the name; in 3-across the text is hidden, the name still says it). Each card is `role=group` named "Option N". Cards with a real visible label use "Choose <label>" ("Choose Its name"). No word or answer is ever in a pill name. Checked: L1 sitting names "This one, option 1/2/3", groups "Option 1/2/3"; gate pills identical. Note: not the "Choose option N" wording, to keep the visible text inside the accessible name (WCAG 2.5.3).
2. Focus. New `app/src/a11y.js`, called from `teacher.newScreen()` (runs on every mount and every sitting step). It focuses the screen heading (`tabindex=-1`, no ring), or the screen container if there is none. Checked: onboarding, every sitting screen, home and gate all end with `activeElement` = the heading. The gate screen got a visually hidden h2 "Read the word".
3. Live region. `aria-live` is gone from `#app` (verified null). One `#live` (`role=status`, `.sr-only`) outside `#app`; the gate's short status lines ("Yes!", "Let's look again...", "More time added") go through `announce()`. Other screens' inline feedback text is no longer announced (the audio carries it).
4. Time limit. Privacy screen (behind the grown-up gate) has "No time limit on the reading check", stored as setting `noTimeLimit`. Without it a "More time" button sits beside the bar and restarts the window. The bar is now stepped by script (no CSS animation), so it is visible under reduced motion; it has `role=progressbar`. Checked in reduced motion with a 4 s window: bar 38% then 19%, "More time" back to 91%, timeout only after the extended window; with the setting on there is no bar, no button and no timeout.

**Minor, done:** tap targets 48px (`.close` 48x48, `.opt-pick` 75x48, `.btn.small` 48 high); waiting pill is now flat #6a93aa with #0a1f2c tick (5.1:1, 3.2:1 vs the card; track B #74889c / #0b1520), and the row dim no longer fades the pill; explicit `:focus-visible` ring (3px #1b4f6b + white halo, seen on the first Tab); ear button moved into the screen header as its last child so Tab order follows its top-right spot (header order: close, Tilo slot, bar, ear; onboarding has no header, so it sits before `#app`); one h1 per screen (first h2 gets `role=heading aria-level=1` when no h1) and `document.title` = "<heading> - Sound Out"; locked lessons are `aria-disabled` and focusable with an `sr-only` reason via `aria-describedby`, pressing one says the locked note and never opens it (checked); `.tag` #6a4d9a, `.gu-msg` #a8432d.
